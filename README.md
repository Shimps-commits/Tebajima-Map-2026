# 危険個所マップ（出羽島・牟岐大島）

ツアー参加者が自分のスマホで危険個所を確認する、日本語・英語対応の地図アプリです。
**これは試作版です。** 表示中のピンは、すべて「サンプル（ダミー）」です。

> **安全上の大切な注意**
> このアプリは参考情報です。安全を保証するものではありません。
> 前提は「出発前の一覧確認」と「ガイドによる口頭案内」です。スマホの表示だけに頼らないでください。

## 1. できること

| 画面 | 内容 |
|---|---|
| 閲覧（参加者用） | ピンの表示、タップで詳細（日英）、種別・危険度の絞り込み、現在地、一覧表、CSV保存、オフライン準備 |
| 編集（あなた用） | 公開URLの末尾に `?edit=1` を付けると開く。ピンの追加・編集・削除・ドラッグ、種別・危険度の編集、書き出し・読み込み |

- **編集画面は本物の認証ではありません。** URLを知っている人は誰でも開けます。ただし、編集内容は**その人のブラウザの中だけ**に保存されます。公開版は書き換わりません。
- 公開版を書き換えられるのは、GitHubにファイルを置ける人（あなた）だけです。

## 2. 最初の公開（1回だけ）

ここでは、無料の GitHub Pages で公開する手順を書きます。
選んだ理由と、他の選択肢は [docs/hosting.md](docs/hosting.md) にあります。

### 2-1. リポジトリをつくる

1. GitHubにログインします。右上の **「＋」→「New repository」** を押します。
2. **Repository name** に、推測されにくい名前を付けます（例：`dewa-map-2026-xk7`）。
3. **Public** を選びます（無料の GitHub Pages は Public のみです）。
4. **「Create repository」** を押します。

### 2-2. ファイルをアップロードする

1. 作成したリポジトリの画面で **「uploading an existing file」** のリンクを押します。
2. このフォルダの中身（`index.html`、`sw.js`、`css`、`js`、`data`、`vendor`、`icons` などすべて）を、画面にドラッグします。
   - **`scripts` フォルダは不要です。** パソコンで試すとき専用です。
   - 一度にアップロードできるのは100ファイルまでです。このアプリは足ります。
3. 下の **「Commit changes」** を押します。

### 2-3. 公開をオンにする

1. リポジトリ上部の **「Settings」** を押します。
2. 左のメニューの **「Pages」** を押します。
3. **Build and deployment** の **Source** を **「Deploy from a branch」** にします。
4. **Branch** を **`main`**、フォルダを **`/ (root)`** にして、**「Save」** を押します。
5. 1〜3分待って、ページを再読込します。上部に公開URLが出ます。
   - 形：`https://（あなたのユーザー名）.github.io/（リポジトリ名）/`

### 2-4. 確認する

- 公開URLを開き、地図とピンが出ることを確認します。
- 編集画面は、公開URLの末尾に `?edit=1` を付けて開きます。
- 参加者に配るQRコードは、**`?edit=1` の付かない**公開URLから作ってください。

## 3. 打合せで危険個所を入力する

**同じパソコン・同じブラウザ**で、最後まで作業してください。
編集内容は、そのブラウザの中にだけ保存されるためです。

### 3-1. 編集画面を開く

1. 公開URLの末尾に `?edit=1` を付けて開きます。
2. 画面の上部に、黄色い「編集モード」の帯が出ます。

### 3-2. 種別と危険度を決める（先に）

1. **「種別・危険度の編集」** を押します。
2. 種別は、アイコン・日本語・英語・色を変えられます。**「＋ 種別を追加」** で増やせます。
3. 危険度は、記号・名称・色・警告半径を変えられます。**「＋ 危険度を追加」** で増やせます。
4. **「保存」** を押します。
   - 使われている種別・危険度は、削除できません。先にピン側を変更してください。

### 3-3. ピンを追加する

1. **「＋ ピンを追加」** を押します。
2. 地図の、危険個所の位置をクリックします。
3. 表示されたフォームに、日本語と英語で入力します。
   - サンプルの印は、実データでは**チェックを外します**。
   - 英語は、一般的な言い方で書いてください（潮流＝tidal currents、落石＝falling rocks など）。
   - 「実在の危険を断定しない」表現にします（例：「〜することがあります」）。
4. **「保存」** を押します。

### 3-4. ピンを直す・動かす・消す

- **直す**：ピンをクリックして、フォームを書き換えて保存します。
- **動かす**：ピンをドラッグします。放した位置で保存されます。
- **消す**：ピンをクリックして、フォームの **「削除」** を押します。

### 3-5. 打合せの最後に（重要）

1. **「書き出し」** を押します。
2. `hazards.geojson` と `categories.json` の**2つ**が保存されます。
   - ブラウザが「複数のファイルのダウンロード」を確認してきたら、**許可**してください。
3. 保存先（通常は「ダウンロード」フォルダ）を確認します。

> 画面上の「このブラウザに自動保存済み」は、**バックアップではありません。**
> ブラウザのデータを消すと失われます。必ず「書き出し」をしてください。

## 4. 入力した内容を公開版に反映する

1. GitHubで、リポジトリを開きます。
2. **`data`** フォルダを開きます。
3. 右上の **「Add file」→「Upload files」** を押します。
4. 書き出した **`hazards.geojson` と `categories.json`** を、画面にドラッグします。
   - **同じ名前のファイルは、上書きされます。**
5. 下の **「Commit changes」** を押します。
6. 1〜3分待ちます。公開URLを開き直して、反映を確認します。

> 参加者のスマホは、**電波があるときに開くと、最新のデータに自動で更新**されます。
> 出発前に、電波のある場所で1回開くよう、案内してください（[8章](#8-参加者への案内オフライン準備)）。

### 一覧をCSVで保存する（補助金の報告資料用）

1. 公開版（または編集画面）で、右上の **「一覧」** を押します。
2. **「CSVで保存」** を押します。`hazards.csv` が保存されます。
3. Excelで開けます。「サンプル」の列が `yes` の行は、ダミーです。報告資料にするときは除外してください。

## 5. 写真を追加する

1. 写真ファイルを用意します（スマホ写真は大きいので、横幅1200px程度に小さくすると、軽くなります）。
2. GitHubの **`photos`** フォルダを開きます。なければ、リポジトリのトップで **「Add file」→「Create new file」** を押し、名前に `photos/README.txt` と入力して作ります。
3. **「Add file」→「Upload files」** で、写真をアップロードし、**「Commit changes」** を押します。
4. 編集画面でピンを開き、**「写真のファイルパス」** に `photos/ファイル名.jpg` と入力して保存します。
5. [4章](#4-入力した内容を公開版に反映する)の手順で、`hazards.geojson` をアップロードします。

> 写真は、参加者がオンラインで一度表示すると、スマホに保存されます。
> 写真が多いと、オフライン準備が重くなります。必要なものに絞ってください。

## 6. 間違えたとき・元に戻したいとき

- **GitHubに間違ったファイルを上げた**：リポジトリ上部の **「Commits」**（時計のアイコン）で履歴を開き、戻したい版の **`<>`（Browse files）** を開きます。`data` のファイルを開いて、ダウンロードし、上書きアップロードします。
- **編集中に、内容がおかしくなった**：編集画面の **「編集内容を破棄」** を押すと、公開中のデータに戻ります。
- **「書き出し」したファイルを読み込み直したい**：編集画面の **「読み込み」** で、`hazards.geojson` と `categories.json` を選びます（2つ同時に選べます）。

## 7. アプリの仕組みを更新したとき

`index.html`、`js`、`css` などを入れ替えたときだけ必要です。**`data` のファイルだけの更新では、不要です。**

1. GitHubで **`sw.js`** を開き、右上の **鉛筆アイコン（Edit）** を押します。
2. 上のほうの `const VERSION = 'v1';` の **`v1` を `v2`** に変えます（次は `v3`、…）。
3. **「Commit changes」** を押します。
4. 参加者のスマホには、次に電波のある場所で開いたときに、入れ替わります。

## 8. 参加者への案内（オフライン準備）

島の電波は弱い可能性があります。**出発前に、電波のある場所（港など）で準備**してもらってください。

1. QRコードから、公開URLを開きます。
2. 右上の **「オフライン」** を押し、「アプリ本体と危険個所データ」が **「保存済み ✓」** になっていることを確認します。
3. 出羽島と牟岐大島の周辺を、拡大・移動しながら**ひととおり見ます**。見た範囲の地図だけが、スマホに保存されます。
4. 機内モードにして、地図、ピン、現在地が出ることを確認します。
5. （おすすめ）ホーム画面に追加します。iPhone：共有ボタン →「ホーム画面に追加」／Android：メニュー →「ホーム画面に追加」。

**注意（参加者にも伝えてください）**
- 見ていない範囲の地図は、オフラインでは出ません。
- 保存内容は、容量不足や、長期間開かなかった場合に消えることがあります。出発前に必ず確認してください。
- 現在地は、スマホのGPSで動きます。位置情報の許可が必要です。**位置情報は、スマホの中だけで使い、外部には送りません。**
- 接近を知らせる通知機能はありません。**「出発前の一覧確認」と「ガイドの案内」が前提**です。

## 9. 自分のパソコンで試す

Windows の PowerShell で、このフォルダを開いて、次を実行します。

```powershell
powershell -File scripts\serve.ps1
```

ブラウザで `http://localhost:8000/` を開きます（編集画面は `http://localhost:8000/?edit=1`）。
止めるときは、PowerShellで Ctrl+C を押します。

> `localhost` は、パソコン自身だけで開けます。スマホの実機テストは、公開したURL（https）で行います。

## 10. 困ったとき

| 症状 | 確認すること |
|---|---|
| 地図が出ない | 電波（オンライン）を確認。初回はオンラインが必要です |
| 更新が反映されない | 1〜3分待つ。それでも出ないときは、ページを閉じて開き直す。電波のある場所で開く |
| 現在地が出ない | 位置情報の許可（端末の設定とブラウザの設定）を確認。https のURLで開いているか確認 |
| 書き出しのファイルが1つしか保存されない | ブラウザの「複数ファイルのダウンロードを許可」を確認 |
| 打合せ後に、編集内容が消えた | 別のパソコン・ブラウザで開いていないか確認。**書き出しを必ずしてください** |

## 11. フォルダ構成

```
├─ index.html          アプリ本体の入口
├─ sw.js               オフライン用（VERSION を更新に使う）
├─ manifest.webmanifest  ホーム画面追加用
├─ robots.txt          検索エンジンに載せない設定
├─ data/
│  ├─ hazards.geojson  危険個所のデータ（唯一の正）
│  └─ categories.json  種別・危険度の定義
├─ photos/             写真（追加したもの）
├─ css/  js/  vendor/  icons/   見た目・動き・部品
├─ docs/               ホスティング比較、スマホ確認手順
└─ scripts/serve.ps1   パソコンで試す用
```
