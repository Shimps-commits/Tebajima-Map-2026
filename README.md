# 出羽島・牟岐大島マップ（危険個所と見どころ）

ツアー参加者が自分のスマホで、**危険個所**を確認し、**見どころ**（お気に入りの場所、生き物の場所、サーフスポットなど）を地図に残せる、日本語・英語対応の地図アプリです。
**これは試作版です。** 表示中のピンは、すべて「サンプル（ダミー）」です。

> **安全上の大切な注意**
> このアプリは参考情報です。安全を保証するものではありません。
> 前提は「出発前の一覧確認」と「ガイドによる口頭案内」です。スマホの表示だけに頼らないでください。

## 1. できること・画面の見かた

| 場所 | 内容 |
|---|---|
| 上のバー | アプリ名、日本語／EN の切替。下の段に、**エリア切替（出羽島・牟岐大島）**。黄色の帯は安全の注意書き（タップで詳しく表示） |
| 右上のボタン | **地図の種類**（淡色地図・標準地図・航空写真・地形図・OpenStreetMap）。その下の **「危険」「見どころ」** ボタンで、それぞれの表示を入／切できます。PCでは＋／－の拡大縮小も出ます |
| 右下の丸いボタン | **現在地**（端末の中だけで使い、外部には送りません） |
| 下のメニュー | **一覧**（危険個所／見どころの切替、検索、CSV保存）／**絞り込み**／**中央の青い「＋」＝見どころを追加**／**オフライン**（出発前の準備）／**情報**（安全のご注意、マイピン、表示設定、出典） |
| 危険個所のピン | 丸・ひし形・八角形。タップで詳細（説明・対処法・写真・現在地からの距離）。危険度は、**形**（丸＝注意、ひし形＝警戒、八角形＝危険）と**「!」の数**でも見分けられます |
| 見どころのピン | **しずく形**。種別の色とアイコン（絶景、生き物・自然、サーフ・海遊び、食・休憩、歴史・文化、お気に入り）。タップで、おすすめポイントとヒントが出ます |

- 画面の色は、スマホの設定に合わせて**ライト／ダーク**が自動で切り替わります。「情報」の中で、手動でも切り替えられます。
- **編集画面**は、公開URLの末尾に `?edit=1` を付けると開きます（[3章](#3-ピンを立てる打合せでの入力)）。
- **編集画面は本物の認証ではありません。** URLを知っている人は誰でも開けます。ただし、編集内容は**その人のブラウザの中だけ**に保存されます。公開版は書き換わりません。
- 公開版を書き換えられるのは、GitHubにファイルを置ける人（あなた）だけです。

## 2. 最初の公開（1回だけ）

ここでは、無料の GitHub Pages で公開する手順を書きます。
選んだ理由と、他の選択肢は [docs/hosting.md](docs/hosting.md) にあります。

### 2-1. リポジトリをつくる

1. GitHubにログインします。右上の **「＋」→「New repository」** を押します。
2. **Repository name** に、推測されにくい名前を付けます（例：`dewa-map-2026-xk7`）。
3. **Public** を選びます（無料の GitHub Pages は Public のみです）。
4. **「Create repository」** を押します。

### 2-2. ファイルをアップロードする

1. 作成したリポジトリの画面で **「uploading an existing file」** のリンクを押します。
2. このフォルダの中身（`index.html`、`sw.js`、`css`、`js`、`data`、`vendor`、`icons`、`photos`、`docs` など）を、画面にドラッグします。
   - フォルダは、**フォルダごと**ドラッグします。
   - **`scripts` フォルダは不要です。** パソコンで試すとき専用です。
   - 一度にアップロードできるのは100ファイルまでです。このアプリは足ります。
3. 下の **「Commit changes」** を押します。

### 2-3. 公開をオンにする

1. リポジトリ上部の **「Settings」** を押します。
2. 左のメニューの **「Pages」** を押します。
3. **Build and deployment** の **Source** を **「Deploy from a branch」** にします。
4. **Branch** を **`main`**、フォルダを **`/ (root)`** にして、**「Save」** を押します。
5. 1〜3分待って、ページを再読込します。上部に公開URLが出ます。
   - 形：`https://（あなたのユーザー名）.github.io/（リポジトリ名）/`

### 2-4. 確認する

- 公開URLを開き、地図とピンが出ることを確認します。
- 編集画面は、公開URLの末尾に `?edit=1` を付けて開きます。
- 参加者に配るQRコードは、**`?edit=1` の付かない**公開URLから作ってください。

## 3. ピンを立てる（打合せでの入力）

**同じパソコン・同じブラウザ**で、最後まで作業してください。
編集内容は、そのブラウザの中にだけ保存されるためです。

### 3-1. 編集画面を開く

1. 公開URLの末尾に `?edit=1` を付けて開きます。
   - 例：`https://shimps-commits.github.io/Tebajima-Map-2026/?edit=1`
2. **画面のふちがオレンジ色**になり、上に「編集モード」と出ます。
3. PCでは、**左に「編集メニュー」**が出ます。スマホでは、下のメニューの **「編集」** を押すと出ます。

### 3-2. 種別と危険度を決める（先に）

1. 編集メニューの **「種別・危険度の編集」** を押します。
2. 種別は、**危険個所用**と**見どころ用**に分かれています。それぞれ、**アイコン**（左端の丸を押すと選べます）・日本語名・英語名・**色**を変えられます。**「危険個所の種別を追加」「見どころの種別を追加」** で増やせます。
3. 危険度は、**危険個所だけ**に使います。記号・名称・色・警告半径を変えられます。**「危険度を追加」** で増やせます。
4. **「保存」** を押します。
   - 使われている種別・危険度は、削除できません。先にピン側を変更してください。

### 3-3. ピンを立てる（3ステップ）

| ステップ | 操作 |
|---|---|
| **1. 追加を押す** | PC：左メニュー上部の **「＋ 危険個所」**（オレンジ）または **「＋ 見どころ」**（赤）。スマホ：下のメニュー中央の青い **「＋」** を押して、「危険個所を追加」か「見どころを追加」を選ぶ |
| **2. 場所を指定する** | 地図の、その場所を**クリック**（スマホは**タップ**）。PCでは、マウスに**薄いピン**がついてきます。地図を動かして **「中央に置く」** を押すこともできます。やめるときは **「キャンセル」** か Esc キー |
| **3. 内容を入力して保存** | 左のパネル（スマホは下のシート）で、危険個所は **① 種別 → ② 危険度 → ③ 内容**、見どころは **① 種別 → ② 内容** の順に入力し、**「保存」** を押します |

- フォームの一番上の **「危険個所／見どころ」** で、あとから種類を切り替えることもできます。
- 見どころの内容は、**「おすすめポイント」**（なぜ良いか）と**「ヒント・楽しみ方」**（いつ・どう楽しむか）です。安全に関わることは、危険個所として登録してください。

- 入力しているあいだ、**地図上のピンが、選んだ種別・危険度に合わせて変わります**。
- ピンの位置は、**そのままドラッグ**して直せます（フォームを開いたままで構いません）。
- ③ 内容は、**「日本語」「English」のタブ**で切り替えます。入力が空のタブには、**オレンジの●**が出ます。
  - 英語は、一般的な言い方で書いてください（潮流＝tidal currents、落石＝falling rocks など）。
  - 実在の危険を断定しない表現にします（例：「〜することがあります」）。
- **「サンプル（ダミー）」** のスイッチは、実データでは**オフ**にします。
- 保存すると、**「続けて追加」** のボタンが出ます。**直前の種別・危険度が引き継がれる**ので、続けて入力するときに便利です。
- 名称が空のままだと、保存できません。

### 3-4. ピンを直す・動かす・消す

- **直す**：ピンをクリックして、フォームを書き換えて **「保存」**。
- **動かす**：ピンを**ドラッグ**します。放した位置で保存されます。
- **消す**：ピンをクリックして、フォーム左下の **「削除」** → 確認で **「削除する」**。
- **間違えたら**：編集メニューの **「元に戻す」**（キーボードは Ctrl＋Z）。**「やり直す」**（Ctrl＋Shift＋Z）もあります。

### 3-5. 打合せの最後に（重要）

1. 編集メニューの **「書き出し」** を押します。
2. `hazards.geojson` と `categories.json` の**2つ**が保存されます。
   - ブラウザが「複数のファイルのダウンロード」を確認してきたら、**許可**してください。
3. 保存先（通常は「ダウンロード」フォルダ）を確認します。

> 編集メニューの上に、**「未書き出しの変更あり」**（オレンジ）／**「書き出し済み」**（緑）と出ます。
> 下のメニューの「編集」にオレンジの点が付いているときは、まだ書き出していません。
> 「このブラウザに自動保存済み」は、**バックアップではありません。** ブラウザのデータを消すと失われます。必ず「書き出し」をしてください。

## 4. 入力した内容を公開版に反映する

> **スプレッドシートで管理する場合**（[13章](#13-googleスプレッドシートで管理するおすすめ)）は、この手順は不要です。シートの行を直すだけで、反映されます。

1. GitHubで、リポジトリを開きます。
2. **`data`** フォルダを開きます。
3. 右上の **「Add file」→「Upload files」** を押します。
4. 書き出した **`hazards.geojson` と `categories.json`** を、画面にドラッグします。
   - **同じ名前のファイルは、上書きされます。**
5. 下の **「Commit changes」** を押します。
6. 1〜3分待ちます。公開URLを開き直して、反映を確認します。

> 参加者のスマホは、**電波があるときに開くと、最新のデータに自動で更新**されます。
> 出発前に、電波のある場所で1回開くよう、案内してください（[8章](#8-参加者への案内オフライン準備)）。

### 一覧をCSVで保存する（補助金の報告資料用）

1. 下のメニューの **「一覧」** を押します（編集画面では、編集メニューの **「CSV」** でも保存できます）。
2. **「CSVで保存」** を押します。`hazards.csv` が保存されます。
3. Excelで開けます。「kind」の列が、`hazard`（危険個所）か `spot`（見どころ）です。「sample」の列が `yes` の行は、ダミーです。報告資料にするときは除外してください。
   - 利用者の端末の中の「マイピン」は、CSVに入りません（公開データだけが対象です）。

## 5. 写真を追加する

1. 写真ファイルを用意します（スマホ写真は大きいので、横幅1200px程度に小さくすると、軽くなります）。ファイル名は、半角英数字にします（例：`h001.jpg`）。
2. GitHubの **`photos`** フォルダを開きます。
3. **「Add file」→「Upload files」** で、写真をアップロードし、**「Commit changes」** を押します。
4. 編集画面でピンを開き、**「詳細設定」** の **「写真のファイルパス」** に `photos/h001.jpg` のように入力して保存します。
5. [4章](#4-入力した内容を公開版に反映する)の手順で、`hazards.geojson` をアップロードします。

> 写真は、参加者がオンラインで一度表示すると、スマホに保存されます。
> 写真が多いと、オフライン準備が重くなります。必要なものに絞ってください。

## 6. 間違えたとき・元に戻したいとき

- **GitHubに間違ったファイルを上げた**：リポジトリ上部の **「Commits」**（時計のアイコン）で履歴を開き、戻したい版の **`<>`（Browse files）** を開きます。`data` のファイルを開いて、ダウンロードし、上書きアップロードします。
- **編集中に、内容がおかしくなった**：編集メニューの **「元に戻す」**。それでも直らないときは、**「編集内容を破棄」** を押すと、公開中のデータに戻ります。
- **「書き出し」したファイルを読み込み直したい**：編集メニューの **「読み込み」** で、`hazards.geojson` と `categories.json` を選びます（2つ同時に選べます）。読み込みも、**「元に戻す」** で戻せます。

## 7. アプリの仕組みを更新したとき

`index.html`、`js`、`css` などを入れ替えたときだけ必要です。**`data` のファイルだけの更新では、不要です。**

1. GitHubで **`sw.js`** を開き、右上の **鉛筆アイコン（Edit）** を押します。
2. 上のほうの `const VERSION = 'v4';` の **`v4` を `v5`** に変えます（次は `v6`、…）。
3. **「Commit changes」** を押します。
4. 参加者のスマホには、次に電波のある場所で開いたときに、入れ替わります（画面に「新しいバージョンがあります」と出たら、**「再読み込み」**）。

> 以前のデザイン（`VERSION = 'v1'`）で使っていたファイルが、GitHubに残っている場合があります：
> `css/controls.css`、`css/edit.css`、`css/list.css`。使われていないので、**そのままでも動きます**。
> 気になる場合は、GitHubでそのファイルを開き、右上の「…」→「Delete file」で削除できます。

## 8. 参加者への案内（オフライン準備）

島の電波は弱い可能性があります。**出発前に、電波のある場所（港など）で準備**してもらってください。

1. QRコードから、公開URLを開きます。
2. 下のメニューの **「オフライン」** を押し、「アプリ本体と危険個所データ」が **「保存済み」** になっていることを確認します。
3. 出羽島と牟岐大島の周辺を、拡大・移動しながら**ひととおり見ます**。見た範囲の地図だけが、スマホに保存されます（「保存済みの地図」の枚数が増えます）。
4. 機内モードにして、地図、ピン、現在地が出ることを確認します。
5. （おすすめ）ホーム画面に追加します。iPhone：共有ボタン →「ホーム画面に追加」／Android：メニュー →「ホーム画面に追加」。

**注意（参加者にも伝えてください）**
- 見ていない範囲の地図は、オフラインでは出ません。
- 保存内容は、容量不足や、長期間開かなかった場合に消えることがあります。出発前に必ず確認してください。
- 現在地は、スマホのGPSで動きます。位置情報の許可が必要です。**位置情報は、スマホの中だけで使い、外部には送りません。**
- 接近を知らせる通知機能はありません。**「出発前の一覧確認」と「ガイドの案内」が前提**です。

## 9. 自分のパソコンで試す

Windows の PowerShell で、このフォルダを開いて、次を実行します。

```powershell
powershell -File scripts\serve.ps1
```

ブラウザで `http://localhost:8000/` を開きます（編集画面は `http://localhost:8000/?edit=1`）。
止めるときは、PowerShellで Ctrl+C を押します。

> `localhost` は、パソコン自身だけで開けます。スマホの実機テストは、公開したURL（https）で行います。

## 10. 困ったとき

| 症状 | 確認すること |
|---|---|
| 地図が出ない | 電波（オンライン）を確認。初回はオンラインが必要です |
| 更新が反映されない | 1〜3分待つ。それでも出ないときは、ページを閉じて開き直す。電波のある場所で開く |
| 古いデザインのまま | 電波のある場所で開き直す。画面に「新しいバージョンがあります」と出たら「再読み込み」。出ないときは、`sw.js` の `VERSION` を上げる（[7章](#7-アプリの仕組みを更新したとき)） |
| 現在地が出ない | 位置情報の許可（端末の設定とブラウザの設定）を確認。https のURLで開いているか確認 |
| 書き出しのファイルが1つしか保存されない | ブラウザの「複数ファイルのダウンロードを許可」を確認 |
| 打合せ後に、編集内容が消えた | 別のパソコン・ブラウザで開いていないか確認。**書き出しを必ずしてください** |
| ピンが置けない | 「＋ 危険個所」「＋ 見どころ」を押したあと、地図の上を直接クリック（タップ）します。左のパネルの上ではありません |
| マイピンが消えた | マイピンは、**その端末のそのブラウザの中だけ**に保存されます。ブラウザのデータを消したり、別の端末・ブラウザで開いたりすると、見えません。大切なものは「運営に送る」か「ファイルで保存」をしてください |

## 11. フォルダ構成

```
├─ index.html          アプリ本体の入口
├─ sw.js               オフライン用（VERSION を更新に使う）
├─ manifest.webmanifest  ホーム画面追加用
├─ robots.txt          検索エンジンに載せない設定
├─ data/
│  ├─ hazards.geojson  危険個所と見どころのデータ（唯一の正。ファイル名は、そのままです）
│  ├─ categories.json  種別・危険度の定義（危険個所／見どころの区分、アイコン名、色を含む）
│  └─ config.json      スプレッドシートのURL・提案の受付URL・運営のメール（どれも任意。13章）
├─ sheet/              スプレッドシート連携用（Code.gs＝Apps Script、pins-template.csv＝サンプル）。アップロードは任意
├─ photos/             写真（追加したもの）
├─ css/style.css       見た目（ライト／ダーク）
├─ js/                 動き（地図、ピン、編集、オフラインなど）
├─ vendor/leaflet/     地図ライブラリ
├─ icons/              アプリのアイコン
├─ docs/               ホスティング比較、スマホ確認手順
└─ scripts/serve.ps1   パソコンで試す用
```

## 12. 見どころマップとして使う（マイピン・利用者の提案）

このアプリは、危険個所だけでなく、**島の見どころ**も同じ地図に載せられます。
たとえば、島に来た人が「素晴らしいと思った場所」「いつものお気に入りの場所」「珍しい生き物がいる場所」「サーフスポット」を記録できます。

### 12-1. 見どころの種類（たたき台）

絶景・景色／生き物・自然／サーフ・海遊び／食・休憩／歴史・文化／お気に入り。
打合せで、[3-2](#3-2-種別と危険度を決める先に) の手順で、名前・アイコン・色を変えたり、増やしたりできます。

### 12-2. 運営（あなた）が見どころを登録する

[3章](#3-ピンを立てる打合せでの入力) と同じです。編集メニューの **「＋ 見どころ」** を押して、地図をクリックし、内容を入力して保存します。
最後に「書き出し」→ GitHubに上書き、で公開版に反映されます。

### 12-3. 利用者が「マイピン」を残す

1. 下のメニュー中央の青い **「＋」** を押します。
2. 地図をタップして、場所を指定します。
3. 種別、**なまえ**、**おすすめポイント**、ニックネーム（任意）を入力して、**「保存」** を押します。
   - 英語の画面で入力すると、英語で保存されます（日本語で入れても構いません）。
4. **マイピンは、その人の端末の中だけ**に保存されます。ほかの人には見えません。ピンには、小さな人のマークが付きます。
5. 「情報」を開くと、マイピンの一覧と、**「すべて運営に送る」「ファイルで保存」「すべて削除」** があります。

> 利用者の位置情報や入力内容は、**利用者が自分で「運営に送る」を押すまで、どこにも送信されません。**

### 12-4. 利用者の提案を、みんなの地図に載せる

このアプリには、サーバー（データを預かる場所）がありません。そのため、利用者のピンが、自動でみんなの地図に載ることはありません。
**運営が内容を確認してから、取り込む**流れです（不適切な投稿や、危険な場所の誤った案内を防げます）。

1. 利用者が、マイピンの詳細（または「情報」）で **「運営に送る」** を押します。
2. 出てきた画面で、**「共有する」**（LINEなど）、**「メールで送る」**、**「コピーする」** のどれかを選びます。
   - 送られるのは、なまえ、場所、おすすめポイント、ニックネームです。メッセージの最後に、運営用のデータ（`HAZMAP1:` で始まる1行）が付きます。
   - 「メールで送る」を出したいときは、GitHubの `data/config.json` の `"contactEmail"` に、運営のメールアドレスを入れます。
3. 届いたメッセージを、運営（あなた）が確認します。
4. **編集画面**（`?edit=1`）を開き、編集メニューの **「利用者の提案を取り込む」** を押します。
5. 届いたメッセージを、**そのまま貼り付け**ます（ファイルでも取り込めます）。件数と名前が出ます。
6. **「取り込む」** を押します。見どころとして追加されます（「みんなの投稿」の印が付きます）。
7. 内容を確認し、必要なら、英語の追加や種別の変更をします。
8. 「書き出し」→ GitHubに上書き、で公開します。

### 12-5. 将来：みんなで、リアルタイムに共有する

「投稿したら、すぐに全員の地図に出る」ようにするには、データを預かるサーバー（例：Supabase）が必要です。
その場合は、投稿の確認（承認）の仕組みや、不適切な投稿への対応、個人情報の扱いも、あわせて決める必要があります。
この構成から、あとで移行できます。

## 13. Googleスプレッドシートで管理する（おすすめ）

GitHubへのアップロードの代わりに、**スプレッドシートの行を直すだけで、地図が更新される**ようにできます。
さらに、利用者が「運営に送る」を押すと、**提案が、スプレッドシートに自動で入ります**。

```
        ┌────────────── Googleスプレッドシート ──────────────┐
利用者 →│ 「提案」タブ（非公開）  →  確認  →  「ピン」タブ（公開） │→ 地図に表示
 送信   └──────────────────────────────────────────────┘
```

| タブ | 役割 | 公開 |
|---|---|---|
| **ピン** | 地図に出す内容。**「公開」にチェックした行だけ**が出ます | ウェブに公開（CSV） |
| **提案** | 利用者から届いた提案が、自動で追記されます | **公開しません** |
| **種別** | 種別の名前の参考表（選択肢に使います） | 公開しません |

> この設定は、あなたのGoogleアカウントでの操作です。Googleの画面は変わることがあり、名前が少し違う場合があります。
> **1回だけ**の設定です（30分ほど）。設定しなくても、アプリはこれまでどおり動きます（同梱の `hazards.geojson` を使います）。

### 13-1. スプレッドシートを作る（1回だけ）

1. Googleドライブで、新しい**スプレッドシート**を作ります（名前の例：`出羽島マップ データ`）。
2. メニューの **「拡張機能」→「Apps Script」** を開きます。
3. 最初から入っている `function myFunction() {}` を**消して**、このフォルダの **`sheet/Code.gs`** の中身を、**全部コピーして貼り付け**ます。
4. 上の **「保存」**（フロッピーのアイコン）を押します。
5. スプレッドシートの画面に戻り、**ページを再読み込み**します。メニューに **「地図」** が出ます。
6. **「地図」→「初期設定（最初に1回）」** を押します。
   - 初回は、「承認が必要です」と出ます。**「続行」→ アカウントを選ぶ → 「詳細」→「（プロジェクト名）に移動」→「許可」** の順に進みます。
   - 「このアプリは Google で確認されていません」と出ますが、**あなた自身が作ったスクリプト**なので、問題ありません。
7. 終わると、**「ピン」「提案」「種別」** のタブができます。

### 13-2. いまのサンプルを入れる（任意）

1. 「**ピン**」タブを開きます。
2. **「ファイル」→「インポート」→「アップロード」** で、**`sheet/pins-template.csv`** を選びます。
3. 「インポートの場所」は **「現在のシートを置換する」** を選び、**「データをインポート」** を押します。
4. もう一度、**「地図」→「初期設定」** を押します（チェックボックスや選択肢が、元に戻ります）。

### 13-3. 「ピン」タブを、ウェブに公開する

1. **「ファイル」→「共有」→「ウェブに公開」** を押します。
2. 「リンク」のタブで、左側を **「ピン」** （シート全体ではなく、このタブだけ）、右側を **「カンマ区切り形式（.csv）」** にします。
3. **「公開」** を押し、出てきた**URL**をコピーします。
   - `https://docs.google.com/spreadsheets/d/e/……/pub?gid=……&single=true&output=csv` のような形です。
4. **「提案」タブと「種別」タブは、公開しないでください**（このURLは「ピン」だけです）。

### 13-4. 提案の受付口（Apps Script）を作る

1. もう一度、**「拡張機能」→「Apps Script」** を開きます。
2. 右上の **「デプロイ」→「新しいデプロイ」** を押します。
3. 歯車のアイコンで、種類に **「ウェブアプリ」** を選びます。
4. 次のように設定します。
   - **次のユーザーとして実行：自分**
   - **アクセスできるユーザー：全員**
5. **「デプロイ」** を押し、出てきた**ウェブアプリのURL**（`https://script.google.com/macros/s/……/exec`）をコピーします。
   - もう一度、承認の画面が出たら、13-1 と同じように進みます。

### 13-5. アプリに、2つのURLを設定する

1. GitHubで、**`data`** フォルダの **`config.json`** を開き、右上の **鉛筆アイコン（Edit）** を押します。
2. 2つのURLを、ダブルクォート `" "` の間に貼り付けます。

   ```json
   {
     "sheetCsvUrl": "（13-3 でコピーしたCSVのURL）",
     "submitUrl": "（13-4 でコピーしたウェブアプリのURL）",
     "contactEmail": ""
   }
   ```
3. **「Commit changes」** を押します。
4. 1〜3分後、公開URLを開き直します。「情報」の下に、**「データの更新：…」** と出れば、つながっています。

> `sheetCsvUrl` だけ入れれば、**地図の読み込みだけ**スプレッドシートになります。
> `submitUrl` を入れると、利用者の「運営に送る」が、**「送信する」ボタンで直接送れる**ようになります。

### 13-6. ふだんの使い方

- **ピンを足す・直す・消す**：「ピン」タブの行を、直接編集します。
  - **公開**にチェック（✓）した行だけが、地図に出ます。チェックを外すと、地図から消えます。
  - **種類**：`危険個所` か `見どころ`。**種別**：選択肢から選びます（「種別」タブの日本語名）。
  - **危険度**：危険個所だけ（1〜3）。見どころは、空にします。
  - **緯度・経度**：数字で入れます。**調べかた**は、下の「座標の調べかた」を見てください。
  - **サンプル**：チェックすると、画面に「サンプル」と出ます。実データでは、外します。
- **反映のタイミング**：直してから、**数分**で地図に反映されます（Google側の更新に、時間がかかります）。
- **座標の調べかた**：編集画面（`?edit=1`）でピンを置き、編集メニューの **「シート用にコピー（全件）」** を押して、シートの **「ピン」タブの A1** に貼り付けます（今ある内容は、置き換わります）。または、国土地理院の地図などで調べた座標を、入力します。
- **オフラインのとき**：利用者のスマホは、**前回取得したデータ**を表示します。

### 13-7. 利用者の提案を受け取る

1. 利用者が、マイピンから **「運営に送る」→「送信する」** を押します。
2. スプレッドシートの **「提案」タブ**に、**自動で行が増えます**（状態：未確認）。
3. 内容を確認します（不適切な内容や、場所の誤りがないか）。
4. 載せたい行を選び（行番号をクリック。複数可）、メニュー **「地図」→「選択した提案を「ピン」に追加」** を押します。
5. 「ピン」タブに、**公開にチェックが入った行**が追加されます。必要なら、英語の追加や、種別の変更をします。
6. 数分で、みんなの地図に出ます。「提案」タブの状態は、**「採用」**になります。載せない行は、そのままで構いません。

### 13-8. 注意（必ず読んでください）

- **「ピン」タブは、公開されます。** URLを知る人は、中身をだれでも読めます。**個人情報（氏名、連絡先など）は、入れないでください。**
- **「提案」タブは、公開されません。** ただし、受付口のURLは `config.json` に入るため、**だれでも、提案を送れます**。スパムが入る可能性があります。内容を確認してから載せる流れなので、地図に直接は出ません。1回に5件まで、長さの上限があり、式（`=` で始まる文字）は無効にします。
- **危険個所の登録は、必ず運営の確認が前提です。** 利用者のマイピンは、見どころだけです。
- 「ピン」タブの**見出し（1行目）の名前は、変えないでください**。列の順番は、変えても動きます。
- 新しい**種別**をアプリの編集画面で増やしたら、**「種別」タブにも1行足して**ください（選択肢に出ます）。名前は、アプリの種別名と、同じにします。
- 「ウェブに公開」を止めたいときは、**「ファイル」→「共有」→「ウェブに公開」→「公開を停止」**。そのあとは、同梱の `hazards.geojson` が使われます。
- 受付口のURLを変えたいとき（スパム対策など）は、Apps Script で**新しいデプロイ**を作り、`config.json` を入れ替えます。古いデプロイは、「デプロイを管理」から、無効にできます。
